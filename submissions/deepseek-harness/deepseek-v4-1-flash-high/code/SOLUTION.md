# Лендинг студии маникюра «Лак&Точка» — решение

Модуль `bxmax.booking` в `local/modules/`, лендинг на главной странице, инфоблоки
`services` и `masters` создаются и наполняются кодом. Стенд: <http://ai.bitrix:8765/>

## Reference

**URL сайта:** <https://venetianspa.ca/>
**Карточка awwwards:** <https://www.awwwards.com/sites/venetian-nail-spa> (Honorable Mention)

### Почему он

Это единственный из просмотренных бьюти-лендингов, у которого весь дизайн-слой открыт и
читается: китовые токены Elementor (палитра, типографика, контейнер), постраничный CSS с
точными `px/em/hex/letter-spacing`, `@font-face` с прямыми `.woff2` и кастомный GSAP-код
инлайном. Ниша совпадает с задачей до последней секции: nail spa с онлайн-записью, услугами,
командой и локацией. И главное — у него узнаваемый язык: золото на кремовом, гигантский
display-сериф, архитектурные арки, «жалюзи» в hero и скраб-морфинг радиусов.

### Шрифты и палитра

**Референс:** `Beautique Display` (коммерческий display-сериф, Befonts) + `Inter-V`.
**У меня:** **Playfair Display** (SIL OFL, есть кириллица — обязательна для русского
контента) + **Inter** (OFL, как у референса). Оба лежат локально в
`assets/fonts/*.woff2` (сабсеты cyrillic / cyrillic-ext / latin / latin-ext) с
`unicode-range`, без обращений к внешним CDN.

**Палитра референса:** `#B69F64` (primary), `#ECE8DF` (фон), `#CEC6B3` (accent),
`#FFFFFF` (текст на золоте), `#ECE8DFD1` в радиальном градиенте арки.

**Моя палитра** — те же тона, но с поправкой на контраст (см. Deviations):
`--c-cream #ECE8DF`, `--c-cream-soft #F4F1EA`, `--c-gold #B69F64`,
`--c-gold-deep #9A8248` (крупные заголовки), `--c-accent-ink #6F5A2A` (кнопки, ссылки,
мелкий акцентный текст), `--c-gold-dark #A98E52` (золотые секции),
`--c-ink-on-gold #2F2617` (мелкий текст на золоте), `--c-ink #4A4133`,
`--c-ink-soft #6B6046`.

**Шкала:** h1 `clamp(34px, 6.2vw, 90px)` / 1.09 / −0.004em (как 90px/1.09em референса),
h2 `clamp(27px, 4.4vw, 65px)`, карточка `clamp(20px, 2.2vw, 34px)` / 1.03 / −0.014em,
h3 25px/1.32, текст 15px/1.55, мета 12px. Контейнер 1200px, вертикальный ритм — только
паддингами (`clamp(64px, 9vw, 150px)`), вынос блока из сетки через
`calc((100% - 1200px) / 2)`, радиусы 450/140/28–32/999px, бордер 1px, **теней нет**.

### Пять приёмов, которые воспроизведены

1. **Hero-«жалюзи»** — 52 вертикальные полосы цвета `#B69F64` с `transform-origin: left
   center`, раскрываются `rotateY(0 → −90deg)` со stagger 9 мс на полосу; после раскрытия
   контейнер скрывается (`visibility: hidden`), как в референсе после scrub-прохода.
2. **Заголовок по символам** — свой сплиттер (без SplitType) режет h1 на слова и символы;
   каждый `.char` выезжает `translateY(30px) → 0`, `opacity 0 → 1`, stagger 26 мс.
3. **Скраб-морфинг арки** — радиус верха арки едет `1250px → 450px` по прогрессу скролла
   (`border-radius` в CSS-переменной, rAF-троттлинг, только >1024px).
4. **Reveal изображений** — `clip-path: polygon(0 0,0 0,0 0,0 0) → polygon(0 0,100% 0,100%
   100%,0 100%)` за 1 с плюс `scale(1.5) → 1` у картинки.
5. **Микроинтеракции** — кнопки с инверсией за 0.7 с (`transparent + 1px` ↔ заливка),
   подчёркивание ссылок через `text-decoration-color` за 0.1 с при
   `text-underline-offset: 5px`, `skewX(-10deg)` у активного пункта меню, `background`
   параллакс не используется (нет `background-attachment: fixed` из-за мобильных багов).

## Assumptions / Questions / Deviations

**Допущения**

1. Инфоблоки `services`/`masters` — контент сайта, а не данные модуля; модуль владеет только
   своими таблицами. Связь — по ID элемента инфоблока.
2. Все данные студии (адрес, телефон, цены, отзывы, имена мастеров) вымышлены.
3. Часовой пояс — серверный (Europe/Moscow). `STARTS_AT`/`ENDS_AT` хранятся как `DATETIME`
   без зоны, API отдаёт ISO-8601 со смещением сервера.
4. Получатель письма — `EMAIL` сайта (развёртывание ставит `studio@laktochka.ru`); можно
   переопределить опцией модуля `admin_email`.
5. Развёртывание запускается само из `local/php_interface/init.php` при первом запросе после
   копирования площадки и идемпотентно; версия — в опции `bxmax.booking/deploy_revision`.
   Принудительно: `php local/tools/deploy.php --force`.

**Осознанные отклонения**

6. **Контраст.** В референсе золото `#B69F64` на кремовом `#ECE8DF` даёт 2.07:1 — это ниже
   WCAG AA даже для крупного текста. Тона сохранены, но мелкий текст и интерактив переведены
   в `#6F5A2A`, крупные заголовки — в `#9A8248`, мелкий текст на золоте — в `#2F2617`
   (все ≥ 4.5:1, проверено расчётом и в браузере).
7. **Hero без видео.** Фоновое видео референса не переиспользуем (чужой ассет), среди
   свободных стоков подходящего видео нет. Взят стоп-кадр с золотым скримом; движение несут
   «жалюзи» и посимвольный заголовок.
8. **Шрифт.** `Beautique Display` заменён на **Playfair Display**: у первого не подтверждена
   лицензия и нет кириллицы, у второго — SIL OFL и полный набор русских глифов.
9. **Расширение контракта API.** У `slots.list` добавлен код `VALIDATION` для `weekStart` не
   в формате `YYYY-MM-DD` (в таблице контракта перечислен только `MASTER_NOT_FOUND`).
   Обязательные коды и поля ответа не изменены.
10. **Почта.** Модуль `mail` на стенде не установлен, поэтому очередь `b_event` никто не
    разбирает. Уведомление ставится в очередь как обычное почтовое событие
    `BXMAX_BOOKING_NEW` и сразу же вычитывается `EventManager::executeEvents()`.
11. **Удаление модуля** помечает площадку как развёрнутую (опция `deploy_revision`),
    иначе авторазвёртывание вернуло бы модуль на следующем запросе и удаление было бы
    бессмысленным.
12. **Фильтр в админке** использует нативный `<input type="date">` вместо
    `CAdminCalendar` — меньше JS, поведение то же.
13. **`include.php` у модуля отсутствует:** регистрировать в нём нечего — namespace
    подхватывается ядром, сервисы — из `.settings.php`, таблицы/события/агент — установщиком.
14. **Изображения** — CC0 (rawpixel / StockSnap, через OpenAPI Openverse), локально,
    с общей тёплой цветокоррекцией; ассеты референса не используются. Атрибуция не требуется,
    кроме исключённого кадра с Flickr CC-BY, который заменён на CC0.

**Открытые вопросы**

15. Нужен ли реальный видео-фон в hero (тогда — отдельная съёмка или лицензированный сток)?
16. Остаётся ли заявка в базе после «удаления» (сейчас — жёсткое удаление, слот
    освобождается, как и требует ТЗ)?

## Что сделано (кратко)

* **Модуль `local/modules/bxmax.booking/`**: ORM-таблицы `bxmax_booking_slot` /
  `bxmax_booking_entry`, репозитории, сервисы, контроллеры
  `bxmax:booking.api.slots.list` / `bxmax:booking.api.bookings.create`
  (`\Bxmax\Booking\Controller\Api\*`), почтовое событие `BXMAX_BOOKING_NEW`, агент продления
  расписания, две страницы админки (`CAdminList` + фильтры + групповые действия), компонент
  `bxmax:booking.slots`, установщик/деустановщик.
* **Гарантия «один слот — одна запись»** — уникальный индекс
  `ux_bxmax_booking_entry_slot (SLOT_ID)`; при гонке СУБД отклоняет вставку, сервис
  переводит это в `SLOT_TAKEN`. Проверено 8 параллельными запросами из разных сессий:
  1 успех, 7 `SLOT_TAKEN`.
* **Развёртывание** — `local/php_interface/bxmax_deploy.php` (тип инфоблоков, инфоблоки
  `services`/`masters` с 8 услугами и 4 мастерами, установка модуля, расписание 14 дней ×
  10 слотов × 4 мастера, шаблон сайта), CLI `local/tools/deploy.php [--force]`.
* **Лендинг** — `www/index.php`, шаблон `local/templates/laktochka/`, локальные шрифты,
  картинки и ванильные CSS/JS без библиотек и внешних запросов в рантайме.
* **Версионирование ассетов** — nginx стенда отдаёт статику с
  `Cache-Control: max-age=315360000`, поэтому все локальные CSS/JS/картинки шаблона и скрипт
  компонента подключаются как `?v=<filemtime>` (`lt_asset()` в `functions.php`). Без этого
  браузер держит первую загруженную копию файла и правки вёрстки не видны без жёсткого
  обновления.
